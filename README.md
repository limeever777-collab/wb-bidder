# Биддер WB и Telegram-боты

Проект для Codex: биддер рекламы WB, бот управления биддером и отдельный бот блокировок WB/Ozon.

Это чистая копия актуальной рабочей папки `/Users/d/wb-bidder`. Здесь нет токенов, ключей, состояний, кэша, отчётов и резервных копий. Логика кода не изменена; в подсказке на странице управления Claude заменён на Codex.

## Состав

| Файл | Назначение |
|---|---|
| `bidder.py` | Смотрит статистику рекламы и предлагает или меняет ставки для целевого ДРР |
| `tg.py` | Сообщения, кнопки и обработка ответов Telegram |
| `blocks_watch.py` | Новые и снятые блокировки/скрытия WB и Ozon, ежедневная сводка |
| `config.json` | Актуальные настройки кабинетов, ДРР, лимитов и минус-фраз |
| `автозапуск_com.wb.bidder.plist` | Запуск биддера на Mac каждые 30 минут |
| `автозапуск_com.wb.blocks.plist` | Запуск проверки блокировок на Mac каждые 3 часа |

Сторонние Python-библиотеки не нужны.

## Ключи

В рабочей папке должны быть три файла, которые нельзя загружать в Codex, GitHub, Obsidian или чат:

- `tokens.json` — токены WB;
- `ozon_keys.json` — ключи Ozon;
- `telegram.json` — токены и чаты двух Telegram-ботов.

Их нужно скопировать отдельно с исходного Mac и ограничить доступ:

```bash
chmod 600 tokens.json ozon_keys.json telegram.json
```

Формат `telegram.json`:

```json
{
  "bidder": {"token": "ДОБАВИТЬ_ЛОКАЛЬНО", "chat_id": 123},
  "blocks": {"token": "ДОБАВИТЬ_ЛОКАЛЬНО", "chat_id": 123}
}
```

`chat_id` также может быть списком чатов.

## Запуск

Скопируйте проект в `~/wb-bidder`, добавьте ключи локально, затем:

```bash
cd ~/wb-bidder
python3 -I bidder.py                      # только план по всем кабинетам
python3 -I bidder.py --cab "Swiss Health" # план по одному кабинету
python3 -I blocks_watch.py                # проверка блокировок
```

Команды ниже меняют данные. Запускать их нужно только после отдельного подтверждения:

```bash
python3 -I bidder.py --apply              # записать ставки
python3 -I bidder.py --rollback ФАЙЛ      # восстановить ставки из бэкапа
```

В `config.json` запись сейчас разрешена для Swiss Health и BioNature. Чтобы запретить её, очистите `apply.cabinets`. Не запускайте биддер с записью одновременно на двух компьютерах.

## Автозапуск на Mac

На исходном Mac задания уже установлены:

- `com.wb.bidder` — каждые 30 минут с `--apply`;
- `com.wb.blocks` — каждые 3 часа.

Для установки на другом Mac скопируйте plist-файлы:

```bash
cp автозапуск_com.wb.bidder.plist ~/Library/LaunchAgents/com.wb.bidder.plist
cp автозапуск_com.wb.blocks.plist ~/Library/LaunchAgents/com.wb.blocks.plist
```

Внутри plist указаны пути `/Users/d`. Если на новом Mac другое имя пользователя, сначала замените их на свой домашний каталог. После этого:

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.wb.bidder.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.wb.blocks.plist
```

Остановка:

```bash
launchctl bootout gui/$(id -u)/com.wb.bidder
launchctl bootout gui/$(id -u)/com.wb.blocks
```

Журналы на исходном Mac: `~/Library/Logs/wb-bidder.log` и `~/Library/Logs/wb-blocks.log`.

## Telegram

- **Бот биддера:** предупреждения о высоком ДРР, паузах и бюджете, падении заказов, кнопки подтверждения минус-фраз и сводка после 9:00.
- **Бот блокировок:** новые и снятые блокировки/скрытия по WB и всем кабинетам Ozon, сводка после 13:00.

Для работы кнопок биддер сам получает обновления Telegram при очередном запуске. Отдельный постоянный процесс для `tg.py` не нужен.

## Основная логика биддера

- **ДРР карточки** = весь расход рекламы ÷ все заказы карточки в рублях за окно `lookback_days`, без сегодняшнего дня.
- **ДРР кластера** = расход кластера ÷ (заказы из Джема по запросу × средний чек карточки). Атрибуция заказов WB по кластерам не используется.
- Позиция в рекламе берётся из `avg_pos`; позиции в выдаче — из локального `market.json`. Если файла нет или он старше двух дней, биддер его не учитывает.
- Ставка снижается при ДРР выше цели и достаточном расходе. Подъём допускается при низком ДРР, заказах и выполнении ограничений по позициям.
- При достижении `daily_cap` кампания ставится на паузу; на следующий день биддер запускает её снова.
- Одна и та же ставка обычно меняется не чаще, чем раз в `cooldown_hours`. За один запуск действует `max_changes_per_run`.

### Правила с 07.11.2026

- Главные запросы выбираются автоматически: ВЧ от 2 300 поисков в неделю по Джему, по которым есть заказы. Их удерживают в топ-10, пока ДРР запроса не выше `top_drr_cap`.
- Вручную главные запросы задаются в `cards.<nm>.top`.
- Если ДРР по всем кабинетам за 7 дней выше `weekly_drr_limit`, ставки не поднимаются.
- Кластеры и базовые ставки с низким ДРР и заказами поднимаются раз в сутки на 10%; при ДРР ниже половины цели — на 20%.
- `auto_minus.mode = confirm`: биддер предлагает минус-фразу в Telegram и отключает её только после нажатия кнопки. В режиме `auto` отключение происходит автоматически.
- Перед отключением минус-фразы создаётся резервная копия в `backups/minus_*.json`.

## Управление через Codex

Откройте эту папку как проект Codex. Постоянные правила находятся в `AGENTS.md`.

Можно просить Codex:

- объяснить последний план или код;
- подготовить изменение `config.json`;
- разобрать причину уведомления;
- исправить код и проверить его синтаксис.

Перед любыми изменениями ставок, минус-фраз, конфигурации или автозапуска Codex должен показать план и получить подтверждение.

## Ограничения

- В ручных CPM-кампаниях можно менять ставки кластеров; в единой ставке и CPC — только базовую ставку.
- В CPC-кампаниях минус-фразы через API не принимаются, их нужно вносить вручную.
- Биддер не видит остатки FBS из-за отсутствующей категории токена «Маркетплейс».
